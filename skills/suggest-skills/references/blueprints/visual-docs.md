# 설계도: visual-docs 스킬

조사 결과를 Mermaid 도식과 표를 곁들인 Markdown 문서로 `docs/`에 남긴다.

## description 골격

`{{프로젝트}} 저장소 docs/에 Mermaid 도식(sequenceDiagram·flowchart·stateDiagram·erDiagram)과 표를 곁들인 설명 문서를 작성·수정한다. 처리 흐름도, 시퀀스 다이어그램, 구조도, ERD를 문서로 남기거나 기존 설명 문서 갱신을 요청할 때 사용한다. 채팅으로만 보여 줄 그림, HTML 페이지, 조사 결과의 자동 문서화에는 쓰지 않는다.`

## 본문에 넣을 기준

- 요청받았을 때만 작성한다. 파일을 만들기 전에 `docs/`에서 같은 주제를 찾아 있으면 그 문서를 고친다. 파일명은 짧은 kebab-case.
- 소스·로그에서 현재 구현과 측정값을 확인하고, 측정한 사실과 추정을 구분한다. 결론 한두 문장을 먼저 쓴다.
- 도식 고르기: 요청·이벤트 순서 → sequence, 구성·분기 → flowchart, 생명주기 → state, 데이터 관계 → er, 수치 → 표.
- 정확한 값은 도식 옆 표에, 끝에는 `docs/` 기준 상대 경로 출처와 검증하지 못한 가정.
- 첫 방문과 캐시 적중, HTTP 요청과 DB 쿼리처럼 다른 것을 섞지 않는다. 비밀값·운영 식별자를 넣지 않는다.
- 완료 전: 도식과 표가 일치하는지, Mermaid 펜스 짝, 출처 링크가 열리는지 확인한다. 문서 때문에 앱 코드를 바꾸거나 커밋하지 않는다({{docs/가 Git 추적 대상이면: 커밋은 요청 시 devkit:commit}}).
